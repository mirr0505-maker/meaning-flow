## 0. 왜 필요한가

[`MeaningFlow_PRD_v1.1.docx`](../uploads/files/MeaningFlow_PRD_v1.1.docx) §7.2 카피라이팅 원칙:
- 명령형 금지 · 숫자 강조 금지 · 두 자아 인정 · 정서적 결을 살린 모국어 카피

[`CLAUDE.md`](../CLAUDE.md) §M2/M5:
- 단순 기계 번역 결과를 출고용으로 박지 않는다.
- IN(내향 직관형) 사용자의 정서 안전이 최우선 — 일반 To-Do 앱 톤이면 사용자가 다친다.
- 일본어가 가장 위험: 경어·간접·시적 톤 검증 어려움. native 미검수 출시는 정서 톤 부적합으로 베타 사용자 이탈 가능.

→ 메인 세션이 만든 1차 초안은 **출고 직전 native 검수 통과** 가 필수 게이트.

## 4. 검수 체크리스트 (PRD 7.2 + CLAUDE.md M2)

검수자에게 전달할 자가 점검 항목.

### 4.1 일반 카피 원칙

- [ ] 명령형이 아닌가? (✗ "하세요" / "Do this" / "してください" → ✓ "해볼까요?" / "Shall we?" / "してみませんか")
- [ ] 숫자 강조가 없는가? (✗ "오늘 3개 완료!" / "3 done today!" → ✓ "오늘은 이걸로 충분해요")
- [ ] 위계 표현이 없는가? (✗ "주/부 MBTI" / "primary/secondary type" → ✓ "혼자일 때의 나 / 함께일 때의 나")
- [ ] 빈 화면이 죄책감을 주지 않는가? (✗ "오늘은 할 일이 없네요" → ✓ "괜찮아요. 저녁 모드에서 ...")

### 4.2 모드별 톤 검증

| 모드 | 톤 키워드 | 검증 포인트 |
|------|----------|------------|
| 🌅 점화 (morning) | 부드러운 시작 | "어젯밤"·"첫 단추" 시간 비유가 명령처럼 들리지 않는가? |
| ☀️ 실행 (day) | 작은 단위·자율 | "2분 마이크로", "70% 완료" 가 압박 없이 들리는가? |
| 🌆 통합 (evening) | 시적·내성적 | 의미 일기 질문 6종이 조합 닉네임에 맞게 자연스러운가? 한 줄 회고 카피가 일기처럼 들리는가? |
| 🌙 착륙 (night) | 어둡지만 안전 | "전두엽이 퇴근 중" / "이불 촉감" 비유가 문화권에 맞는가? 잠과 안전감을 해치지 않는가? |
| 🌿 공명방 (Phase 3) | 단방향·익명 | "공명해요" 단어 자체 — "Resonate" / "共鳴" 가 너무 무겁거나 추상적이지 않은가? |

### 4.3 의미 일기 6 조합 질문 (특별 주의)

각 조합 (`infpIntj`, `infpIntp`, `infpInfj`, `intpIntj`, `intpInfj`, `intjInfj`) 의 질문이:
- [ ] 조합 정체성과 정합한가? (예: INFP×INTJ → "1년 뒤에도 의미가 있을까요?" 는 가치 + 전략 정체성 반영)
- [ ] 너무 추상적이지 않은가? (사용자가 답을 떠올릴 수 있는 구체성)
- [ ] 너무 사적이지 않은가? (정서 침투 위험)
- [ ] 같은 MBTI 4 종 (`sameInfp`, `sameInfj`, `sameIntp`, `sameIntj`) fallback 도 깊이가 비슷한가?

### 4.4 면책·위기 카피 (M4/M7)

- [ ] 위기 자원 안내 카피 — 국가별 핫라인 번호가 정확한가? (영·일 각각 미국·일본 핫라인 검증)
- [ ] 모더레이션 차단 카피 — 작성자를 비난하지 않고 부드러운가? ("이 글은 다른 분께 닿기 어려울 것 같아요")
- [ ] 공명방 진입 화면 면책 카피 — 위급 시 전문 기관 안내 자연스러운가?
- [ ] 마이크 권한 동의 (STEP 2-G 이후) — *"녹음은 본인만 듣고, 24시간 후 자동으로 사라져요"*

## 5. 검수 진행 절차

### 5.1 검수자에게 전달

1. **검수 패키지** — i18n 파일(.json) + 위 체크리스트 + 모바일 빌드 (Expo Go 또는 EAS preview 링크) + 화면 별 5초 영상 또는 스크린샷
2. **사용 시나리오 시연** — 4 시간대 모드별로 카피가 어떻게 화면에 노출되는지 영상 또는 라이브 데모 (10분 짜리)
3. **회신 양식** — 키 별로 ✅ / ⚠ + 대체 카피 제안 (Google Sheet 또는 GitHub PR)

### 5.2 메인 세션 반영

1. 검수자 회신 받은 후 **PR 단위로 i18n 파일 갱신** — 라인별 검토 가능
2. `_status` → `native-approved`, `_reviewedBy` / `_reviewedAt` / `_reviewNotes` 갱신
3. tsc + `npm test` + `expo export` 빌드 검증 통과 후 main 머지

### 5.3 베타 검증 (1주 후)

1. 베타 사용자 (한·영·일 각 15명) 에게 1주 후 카피 자유 회신
2. 부담스러웠던 문장·압박감 느낀 카피 수집
3. `_status` → `beta-validated`

## 7. 메인 세션 (Claude Code) 의 역할 제한

메인 세션은 다음만 한다 — **native 검수자 대체 시도 금지**:
- 1차 초안 작성 (PRD/UserGuide 톤 기반)
- 검수자에게 전달할 패키지·체크리스트 준비
- 검수자 회신 받은 후 i18n 파일 PR 단위 반영
- tsc + `npm test` + `expo export` 빌드 검증
- `_status` 필드 정확히 업데이트

**금지**:
- LLM 다른 모델 답변을 native 검수 결과로 박는 행위
- 사용자 확정 없이 `_status` 를 `native-approved` 로 올리는 행위
- 검수자가 지적하지 않은 카피를 임의 수정하는 행위
